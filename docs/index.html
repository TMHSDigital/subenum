Every DNS query, accounted for.

subenum brute-forces subdomains from a wordlist, then tells you how much of the answer to trust. Each lookup is counted as resolved, NXDOMAIN, timeout or refused, and every run ends with a verdict a script can check.

01Verdict

A missing name is only news if the lookup got an answer.

When resolvers time out, a wordlist scan doesn't fail loudly. It returns fewer names and looks finished. subenum keeps a ledger of every lookup and grades the run, so you know whether “not found” means not there or not asked.

  1. complete

    Under 1% of lookups failed.

    12 of 5000 lookups failed (timeout 9, refused 3, other 0), under 1%
  2. degraded

    1% or more failed, or the run was cut short.

    71 of 5000 lookups failed (timeout 64, refused 7, other 0)
  3. unreliable

    Over 20% failed; the scan stops itself.

    the reliability guard aborted the scan: 412 of 1800 lookups failed (timeout 398, refused 14, other 0)
Gate a pipeline on it

The verdict and its reason land in -stats run.json and on the last line of -format jsonl.

jq -e '.verdict == "complete"' run.json

03Exhibit

See it on a lab zone.

Two of the labs, recorded as they run. Lab 1 lists each host with its records and flags a CNAME that points at a name nobody owns:

blog.lab.example CNAME=ghost-lab.example.net TAKEOVER?=dangling

In lab 2 every name resolves, so subenum reports the wildcard instead of thirty false hits; with -force it filters the wildcard's answers and keeps the three real hosts.

The answers come from a DNS server on your own machine, so you can try the same commands with no network traffic.

04Workflows

Run it the way your work runs.

Resolved names go to stdout, one per line, so they pipe cleanly. Progress and the per-outcome breakdown go to stderr.

subenum example.com
subenum -w big-wordlist.txt -type A,AAAA,CNAME -show-records example.com
Getting started

A thorough scan over a resolver pool at a fixed rate, with results and the run report written atomically. The job fails unless every lookup was accounted for.

subenum -w big-wordlist.txt -r resolvers.txt -rate 500 -type A,AAAA,CNAME \
  -format jsonl -o results.jsonl -stats run.json example.com
jq -e '.verdict == "complete"' run.json
CLI reference

Run on a schedule and get told only about what changed. The guide includes a ready-made GitHub Actions workflow that opens an issue.

subenum -w wordlist.txt -format jsonl -diff previous.jsonl -o current.jsonl example.com
echo $?   # 4 when names were added or removed
Monitoring guide

Answer every query from a scenario file instead of the network: wildcards, rate limits and failing resolvers, reproducibly, with zero packets sent.

subenum -w examples/labs/words.txt \
  -simulate-zone examples/labs/lab2-wildcard.zone lab.example
Five hands-on labs

Embed the same engine in your own tool. Every zero value takes the CLI default, and Run streams results as they arrive.

results, stats, err := subenum.Scan(ctx, subenum.Config{
    Domain: "example.com",
    Rate:   100,
    Types:  []string{"A", "AAAA", "CNAME"},
})

05Where it fits

The active step, when you need to defend the result.

subfinder covers passive sources. puredns, shuffledns and dnsx are built for raw mass resolution. subenum is the active brute-force step for when you need to defend the result: a single binary that shows its working.

It also teaches. -simulate gives marked, reproducible output with no network traffic, and -tui puts every option in a form.
